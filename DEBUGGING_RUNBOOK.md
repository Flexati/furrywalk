# Debugging Runbook — Vercel Deployment Failures

> **"If you see X, check Y, use tool Z."**

---

## Pattern 1: Deployment shows "Error" with no build logs

### Symptom
- Vercel dashboard shows `● Error` status
- Build duration: `0ms` or `?`
- No build logs available
- "Unexpected error. Please try again later."

### Immediate Diagnostic
```bash
# Step 1: Inspect the deployment
vercel inspect <deployment-url> --scope <team>

# Step 2: Reproduce locally
vercel build --yes --scope <team>
```

### Common Root Causes
1. **`@vercel/static-build` auto-detection conflict** → See Pattern 2
2. **Root Directory mismatch** → Check `vercel project inspect <name>` → Root Directory
3. **Framework preset overriding vercel.json** → Check dashboard → Settings → Framework
4. **Missing git integration** → Verify repo connection in Vercel dashboard → Git

### Tool: `vercel build --yes`
This is your primary diagnostic tool. It runs the same pipeline as production but locally, producing actual error messages.

## Pattern 2: "No Output Directory named 'public' found"

### Symptom
```
Error: No Output Directory named "public" found after the Build completed.
Configure the Output Directory in your Project Settings.
Alternatively, configure vercel.json#outputDirectory.
```

### Root Cause
Vercel auto-detects a `build` script in `package.json` and treats the project as a static build, expecting a `public/` output.

### Fix
Add explicit `builds` array to `vercel.json`:
```json
{
  "builds": [
    { "src": "api/index.ts", "use": "@vercel/node" }
  ]
}
```

This prevents auto-detection of the static build step.

### Verification
```bash
vercel build --yes
# Should complete without "public" error
# Check: ls .vercel/output/functions/api/index.func/
```

## Pattern 3: Deployment "Ready" but API returns 404

### Symptom
- Dashboard shows green `● Ready`
- Build duration shows `[0ms]`
- `GET /api/health` returns 404

### Root Cause
Same as Pattern 2 — the deployment is "Ready" but no serverless function was actually built. Vercel deployed only static files (none) + routes.

### Fix
Same fix as Pattern 2. Add explicit `builds` array.

### Verification
```bash
vercel inspect <deployment-url>
# Look for: Builds → should NOT be [0ms]
# Look for: functions directory in .vercel/output/
```

## Pattern 4: pnpm lockfile version mismatch warning

### Symptom
```
Detected pnpm-lock.yaml version 9 generated by pnpm@10.x with package.json#packageManager pnpm@9.12.0
```

### Root Cause
Lockfile was generated with pnpm 10.x, but `packageManager` field specifies `pnpm@9.12.0`.

### Fix
Regenerate lockfile with correct pnpm version:
```bash
pnpm install --lockfile-only
```

Or update `packageManager` to match:
```json
{ "packageManager": "pnpm@10.x.x" }
```

### Verification
Run `vercel build --yes` and check for the warning.

## Pattern 5: vercel.json settings ignored

### Symptom
- Changes to vercel.json (rewrites, functions, installCommand) don't take effect
- Routes shown in `vercel inspect` don't match vercel.json

### Root Cause
Dashboard Framework Preset overrides vercel.json when set to anything other than "Other".

### Fix
Set Framework Preset to **"Other"** in Vercel dashboard → Settings → Framework.

### Verification
```bash
vercel project inspect <name> --scope <team>
# Framework Settings → Framework Preset should be "Other"
```

## Quick Reference: Essential CLI Commands

```bash
# List all deployments for a project
vercel list <project-name> --scope <team>

# Inspect a specific deployment
vercel inspect <deployment-url> --scope <team>

# Inspect project settings
vercel project inspect <project-name> --scope <team>

# Run build locally (reproduces production build)
vercel build --yes

# Pull remote env vars and settings
vercel pull --yes

# Deploy from CLI (bypasses git integration)
vercel deploy --prod

# List all projects in team
vercel project ls --scope <team>
```

## Escalation

If none of the above patterns match:
1. Check [Vercel Status](https://www.vercel-status.com/) for platform incidents
2. Run `vercel build --yes` with `--debug` flag for verbose output
3. Check `.vercel/output/builds.json` for detected build steps
4. Verify GitHub repo is accessible and not empty
5. Check Vercel billing/usage limits in dashboard
